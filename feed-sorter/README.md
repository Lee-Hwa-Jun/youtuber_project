# 🔢 Feed Sorter (개인용)

TikTok · Instagram 의 **검색 결과와 프로필 페이지**를 조회수 / 좋아요 / 댓글 / 날짜순으로
다시 정렬하고, 썸네일 위에 스탯을 표시해 주는 **개인용 리서치 도구**입니다.

랭킹 쇼츠를 만들 때 "어떤 클립이 실제로 잘 나갔는지" 한눈에 비교하려고 만들었습니다.

```
정렬 전:  피드가 준 순서 그대로 (무엇이 대박인지 알 수 없음)
정렬 후:  9.8M ▸ 1.5M ▸ 250K ▸ 42K ▸ 3.1K   (한눈에 비교)
```

---

## 🚀 설치 (5분, 웹스토어 불필요)

크롬 웹스토어에 올리지 않고 **폴더째로 직접 설치**합니다.

1. 크롬 주소창에 `chrome://extensions` 를 입력해 엽니다.
2. 오른쪽 위 **개발자 모드** 스위치를 켭니다.
3. 왼쪽 위 **압축해제된 확장 프로그램을 로드** 버튼을 누릅니다.
4. 이 `feed-sorter` 폴더를 **통째로** 선택합니다. (`manifest.json` 이 들어 있는 폴더)
5. 목록에 "Feed Sorter (개인용)"이 나타나면 끝입니다.
6. 툴바의 퍼즐 조각 아이콘 → Feed Sorter 옆 **압정**을 눌러 고정해 두면 편합니다.

> **크롬 102 이상**이면 됩니다. 엣지(Edge), 웨일 등 크로미움 계열 브라우저도 같은 방법으로 설치됩니다.
>
> 코드를 고친 뒤에는 `chrome://extensions` 에서 이 확장의 **새로고침(↻)** 을 누르고,
> 보고 있던 TikTok/Instagram 탭도 새로고침해야 반영됩니다.

### 설치했는데 동작을 안 하면
- TikTok/Instagram 탭을 **F5 로 새로고침**했는지 확인하세요. (설치 전부터 열려 있던 탭에는 안 붙습니다)
- 피드를 **조금 스크롤**해 보세요. 데이터는 사이트가 응답을 보내줄 때 채워집니다.
- `F12 → Console` 에 `[Feed Sorter]` 로 시작하는 경고가 있는지 보세요. 원인과 고칠 위치를 알려줍니다.

## 📖 사용법

확장 아이콘을 누르면 설정 팝업이 열립니다. (한국어 · 다크 톤)

### 1. 정렬
| 버튼 | 기준 |
|---|---|
| 👁 조회수↓ | 조회수 많은 순 |
| ❤ 좋아요↓ | 좋아요 많은 순 |
| 💬 댓글↓ | 댓글 많은 순 |
| 🆕 최신순 / 📜 오래된순 | 게시일 기준 |
| ↩ 원래 순서 | 사이트가 준 원래 순서로 되돌리기 |

- 선택 즉시 현재 페이지가 다시 배열됩니다.
- 스크롤로 새 영상이 로드되면 **자동으로 제자리에 끼워 넣습니다.**
- 아직 데이터가 안 들어온 카드는 **맨 뒤로** 보내고, 데이터가 도착하면 제자리를 찾아갑니다.
- 선택한 정렬은 **사이트별로 기억**됩니다. (TikTok 은 조회수순, Instagram 은 최신순처럼 따로 저장)

### 2. 최소 조회수 필터
숫자를 넣고 **적용**을 누르면 기준 미달 영상이 **흐리게(25%)** 표시됩니다.
지워지는 게 아니라 흐려지기만 하므로, 마우스를 올리면 다시 잘 보입니다. `0` 이면 끕니다.

### 3. 스탯 오버레이
썸네일 왼쪽 아래에 `👁 1.5M · ❤ 220K · 💬 3.4K` 뱃지가 붙습니다.

| 옵션 | 설명 |
|---|---|
| 스탯 뱃지 | 조회수·좋아요·댓글 표시 |
| 조회수 테두리 | **100만+ 금색**, **10만+ 초록**, 그 외 없음 |
| 게시일 표시 | 뱃지에 `3mo ago` 형식으로 추가 |
| 커서 올리면 정확한 업로드 시각 | 카드에 마우스를 올리면 `🕑 2026-09-15 (화) 14:32:05` 처럼 **초 단위 업로드 시각**을 **내 시간대**로 표시 (기본 켜짐) |
| 다운로드 버튼 | 썸네일에 마우스를 올리면 오른쪽 위에 ⬇ 버튼 |
| 해시태그 칩 | 캡션의 `#태그`를 썸네일 왼쪽 위에 칩으로 표시. **클릭하면 그 태그 검색 페이지가 새 탭**으로 열립니다 |

#### 정확한 업로드 시각 (마우스 올리면)
사이트는 "3개월 전" 정도만 보여주지만, 응답 안에는 초 단위 타임스탬프가 들어 있습니다.
카드에 커서를 올리면 그 값을 **내 컴퓨터의 시간대**로 바꿔 툴팁으로 보여줍니다.

```
🕑 2026-09-15 (화) 14:32:05
Asia/Seoul · GMT+9 · 3mo ago
```

- 시간대는 브라우저(OS 설정)에서 읽습니다. 한국에서 보면 `Asia/Seoul`(서울 시각), 미국에서 보면 그 지역 시각으로 자동 변환됩니다. 팝업의 체크박스 옆에 지금 적용 중인 시간대가 표시됩니다.
- 채널(프로필) 페이지에서 쇼츠 목록을 쭉 보며 **몇 시에 올렸는지** 확인할 때 쓰세요. 경쟁 채널의 업로드 시간대 파악에 유용합니다.
- 툴팁은 커서를 따라다니고, 화면 가장자리에서는 안쪽으로 붙습니다. 카드에서 벗어나면 사라집니다.
- 데이터가 아직 안 들어온 카드(뱃지가 없는 카드)에는 툴팁도 뜨지 않습니다.

#### 해시태그 칩
영상 캡션 전문에서 `#태그`를 뽑아 왼쪽 위에 보여줍니다. 한글·유니코드 태그도 잡고,
`#Dog` 와 `#dog` 처럼 대소문자만 다른 중복은 하나로 합칩니다.

- 처음엔 **3개**만 보이고 나머지는 `+N` 으로 접혀 있습니다. `+N` 을 누르면 전부 펼쳐집니다.
- 칩을 누르면 TikTok 은 `tiktok.com/tag/태그`, Instagram 은 `instagram.com/explore/tags/태그/` 가
  **새 탭**으로 열립니다. 카드 자체(영상)는 열리지 않습니다.
- CSV 내보내기에도 `해시태그` 컬럼으로 함께 들어갑니다.

### 4. 영상 저장 (다운로드)
썸네일에 마우스를 올린 뒤 ⬇ 버튼을 누르면 다운로드 폴더 아래
`FeedSorter/` 폴더에 `tiktok_작성자_영상id.mp4` 형식으로 저장됩니다.

- 저장 주소는 **이미 받아 본 응답 안에 들어 있던 미디어 주소**입니다. 따로 요청을 만들지 않습니다.
- 플랫폼 CDN 이 Referer/쿠키를 요구하면 다운로드가 중단될 수 있습니다.
  그때는 콘솔(F12)에 원본 주소와 함께 안내가 찍히니, 그 주소를 새 탭에 붙여넣고
  오른쪽 클릭 → **다른 이름으로 비디오 저장**을 쓰세요.
- 사진(이미지) 게시물은 영상 주소가 없어 버튼이 나오지 않습니다.

> ⚖️ 남의 영상은 **본인 리서치·검토용으로만** 쓰세요. 실제 영상에 사용하려면 원작자 허락이 필요합니다.
> (같은 저장소의 `ranking-shorts-source-manager` 로 라이선스 상태를 관리할 수 있습니다)

### 5. CSV 내보내기
**⬇ 현재 수집 데이터 CSV 내보내기** 를 누르면 지금까지 모인 영상 목록이 파일로 저장됩니다.

| 컬럼 | 영상URL · 플랫폼 · 작성자 · 조회수 · 좋아요 · 댓글수 · 게시일 |
|---|---|

엑셀에서 한글이 깨지지 않도록 BOM 을 붙입니다. 팝업의 **이번 세션 수집** 숫자가
지금까지 모인 개수이고, **현재 화면 매칭**은 그중 지금 화면에 떠 있는 개수입니다.

## 🧩 이 도구가 하지 않는 것

개인 열람 보조 범위를 넘지 않도록 **일부러 뺀** 기능들입니다.

- ❌ **자동 스크롤** — 스크롤은 사용자가 직접 합니다.
- ❌ **대량 크롤링** — 목록을 훑는 백그라운드 작업이 없습니다.
- ❌ **추가 요청 생성** — 사이트에 요청을 새로 보내지 않습니다.
  사용자가 브라우징하면서 **자연히 발생한 응답만 읽습니다.**
- ❌ **외부 전송** — 수집한 데이터는 브라우저 안에만 있고 어떤 서버로도 나가지 않습니다.

## 📂 파일 구조와 역할

```
feed-sorter/
├── manifest.json          확장 정의 (권한·스크립트 등록)
├── icons/                 툴바 아이콘 (16/48/128px)
├── README.md              이 문서
└── src/
    ├── constants.js       ★ API 경로·셀렉터·상수 모음  ← 유지보수는 거의 여기만
    ├── inject.js          [페이지 컨텍스트] fetch/XHR 응답 가로채 데이터 추출
    ├── content.js         [확장 컨텍스트] 카드 매핑·정렬·오버레이·다운로드 요청
    ├── content.css        오버레이(뱃지·테두리·토스트) 스타일
    ├── background.js      chrome.downloads 로 영상 파일 저장
    ├── popup.html/.css/.js 설정 UI (정렬·필터·오버레이·CSV)
```

### 각 파일이 하는 일

**`src/constants.js`**
API 경로 패턴, 링크 정규식, 그리드 셀렉터, 조회수 구간 기준, 숫자/날짜 포맷 함수.
**상수의 유일한 원본**입니다. `content.js` 가 이 값을 읽어 페이지 쪽(`inject.js`)에도 전달하므로
어느 쪽을 고치든 이 파일 하나만 보면 됩니다.

**`src/inject.js`** — 페이지 컨텍스트
`content.js` 가 `<script>` 태그로 페이지에 꽂아 넣습니다. 이때 필요한 상수(API 경로 등)를
`data-fs-config` 속성으로 건네받으므로, **상수 사본을 따로 들고 있지 않습니다.**
`window.fetch` 와 `XMLHttpRequest` 를 감싸서 **응답을 읽기만** 합니다.
원본 동작과 반환값은 그대로 두기 때문에 사이트 기능에 영향이 없습니다.
JSON 을 너비 우선으로 훑어 `{조회수, 좋아요, 댓글, 게시일, 작성자, 영상주소}` 를 뽑아
`CustomEvent('__FEED_SORTER_ITEMS__')` 로 내보냅니다.
최초 로드 시 페이지에 박혀 오는 `SIGI_STATE` / `__UNIVERSAL_DATA_FOR_REHYDRATION__` 도 읽습니다.

**`src/content.js`** — 확장 컨텍스트
페이지에 `inject.js` 를 꽂아 넣고, 받은 데이터를 `Map` 레지스트리에 모으고, 화면의 `<a href=".../video/123">` 링크를 찾아
**영상 id ↔ 카드 DOM** 을 매핑합니다. 클래스명에 의존하지 않고 링크를 기준으로 찾기 때문에
사이트가 클래스명을 바꿔도 대체로 견딥니다.
`MutationObserver` 로 무한 스크롤을, URL 폴링 + `pushState` 후킹으로 SPA 이동을 감지합니다.

**`src/background.js`**
콘텐츠 스크립트는 `chrome.downloads` 를 쓸 수 없어, 다운로드만 여기서 대신 처리합니다.

## 🛠 사이트 구조가 바뀌었을 때

TikTok/Instagram 은 예고 없이 응답 구조와 DOM 을 바꿉니다.
**증상별로 고칠 곳이 정해져 있습니다.** 먼저 `F12 → Console` 에서 `[Feed Sorter]` 경고를 확인하세요.

### 🔍 먼저: 디버그 모드로 상태 확인하기

무슨 일이 일어나는지 모르겠다면 콘솔(F12)에 이렇게 입력하고 새로고침하세요.

```js
localStorage.setItem('fs_debug', '1')   // 끄려면 removeItem('fs_debug')
```

가로챈 응답마다 한 줄씩 찍힙니다.

```
[Feed Sorter·debug] /api/graphql → 12건 추출              ← 잘 되고 있음
[Feed Sorter·debug] /api/graphql → 영상 데이터 없는 응답 (정상)  ← 원래 영상이 없는 응답
```

> **참고: Instagram 의 `/api/graphql` 은 만능 엔드포인트입니다.**
> 알림 개수, 검색창 추천, 프로필 정보 등 영상과 무관한 질의가 같은 주소로 계속 오갑니다.
> 그래서 "영상 데이터 없는 응답 (정상)" 이 많이 찍히는 건 **문제가 아닙니다.**

### 증상 ①: 콘솔에 "영상처럼 보이는 항목 N개를 찾았지만 필드를 읽지 못했습니다"

**이 경고가 뜰 때만** 실제로 JSON 필드 이름이 바뀐 것입니다.
경고에 **샘플 항목의 키 목록**이 함께 찍히고, 항목 원본은 콘솔에서 이렇게 볼 수 있습니다.

```js
window.__FS_LAST_UNPARSED__
```

1. 위 키 목록에서 조회수·좋아요에 해당하는 새 필드명을 찾습니다.
2. **`src/inject.js`** 의 아래 함수에서 필드명을 고칩니다.

| 플랫폼 | 고칠 함수 | 지금 읽는 필드 |
|---|---|---|
| TikTok | `tiktokItem()` | `id`, `author.uniqueId`, `stats/statsV2 의 playCount·diggCount·commentCount·shareCount`, `createTime`, `video.downloadAddr / video.playAddr` |
| Instagram | `instagramItem()` | `code`/`shortcode`, `user.username`/`owner.username`, `play_count`/`ig_play_count`/`view_count`/`video_view_count`, `like_count`/`edge_liked_by.count`, `comment_count`/`edge_media_to_comment.count`, `taken_at`/`taken_at_timestamp`, `video_versions[0].url` |

> 두 함수는 **JSON 어디에 있든** 그 모양의 객체를 찾아냅니다.
> 응답이 감싸이는 구조(`data[].item`, `itemList[]`, `edges[].node` 등)가 바뀌어도
> **필드 이름만 그대로면 코드를 고칠 필요가 없습니다.**

### 증상 ②: 뱃지가 안 뜨는데 콘솔에 경고도 없다

디버그 모드를 켰는데 **아무 줄도 안 찍힌다면** 애초에 응답을 들여다보지 않은 것입니다.
API 경로가 바뀌었습니다.

1. `F12 → Network` → **Fetch/XHR** 필터로 스크롤 시 오는 요청 경로를 확인합니다.
2. **`src/constants.js`** 의 `API_PATTERNS` 배열에 그 경로 조각을 추가합니다.

```js
TIKTOK: {
  API_PATTERNS: [
    '/api/search/',
    '/api/post/item_list',
    '/api/새로운경로',        // ← 여기에 추가
```

### 증상 ③: 콘솔에 "카드 N개를 찾았지만 … 매칭되지 않았습니다"

데이터는 들어왔는데 **화면의 카드와 이어붙이지 못한** 경우입니다. 영상 링크 형식이 바뀌었습니다.
**`src/constants.js`** 의 `ITEM_LINK_RE` 를 실제 링크에 맞게 고칩니다.

```js
TIKTOK:    ITEM_LINK_RE: '/@([\\w.\\-]+)/video/(\\d+)'   // 캡처1=계정, 캡처2=영상id
INSTAGRAM: ITEM_LINK_RE: '/(?:reel|reels|p|tv)/([A-Za-z0-9_\\-]{5,})'  // 캡처1=shortcode
```
> TikTok 은 **두 번째** 캡처, Instagram 은 **첫 번째** 캡처를 키로 씁니다. 순서를 지켜주세요.

### 증상 ④: 정렬이 엉뚱한 영역까지 건드리거나, 사이드바 링크까지 잡는다

탐색 범위가 너무 넓은 것입니다. **`src/constants.js`** 의 `GRID_SELECTORS` 에
피드 컨테이너 셀렉터를 추가하세요. 여기에 맞는 요소가 있으면 그 안에서만 카드를 찾고,
없으면 문서 전체를 훑습니다. (**이 셀렉터가 틀려도 동작은 합니다** — 범위를 좁히는 힌트일 뿐입니다)

## ⚠️ 알려진 한계

- **React 가 화면을 다시 그리면 정렬이 잠깐 원래대로 돌아갈 수 있습니다.**
  MutationObserver 가 감지해 다시 정렬하므로 보통 0.2초 안에 복구됩니다.
- **스크롤 중에는 재정렬을 하지 않습니다.** 손을 뗀 뒤 0.25초가 지나야 새 카드를 정렬 자리에 끼워 넣습니다.
  그때도 보고 있던 카드의 화면 위치를 계산해 스크롤을 보정하므로, 위쪽에 카드가 끼어들어도
  시야가 튕기지 않습니다. (v1.0 에서 무한 스크롤 때 화면이 위로 튀던 문제의 수정)
- **로그인 전 / 첫 화면 몇 개는 데이터가 없을 수 있습니다.** 페이지가 초기 JSON 을
  주지 않는 경우가 있어서, 스크롤해서 다음 응답이 와야 채워집니다.
- **사진(이미지) 게시물은 조회수가 없습니다.** 좋아요·댓글만 표시되고, 조회수 정렬에서는 뒤로 갑니다.
- **Instagram 은 릴스 탭에서 조회수가 가장 잘 잡힙니다.** 일반 그리드는 응답에 따라 좋아요만 올 수 있습니다.
- **Instagram 키워드 검색(`/explore/search/keyword/`)** 은 결과가 `/api/graphql` 로 오며,
  같은 주소로 영상과 무관한 질의도 잔뜩 오갑니다. 디버그 모드의 "영상 데이터 없는 응답 (정상)"
  줄이 많이 보이는 것은 문제가 아닙니다.
- 확장을 지우면 수집 데이터도 사라집니다. 남겨야 할 자료는 **CSV 로 내보내 두세요.**

## 🔒 권한을 이렇게만 쓴 이유

| 권한 | 용도 |
|---|---|
| `storage` | 정렬·필터·오버레이 설정을 브라우저에 저장 |
| `downloads` | ⬇ 버튼으로 영상 파일 저장 |
| `*://*.tiktok.com/*`, `*://*.instagram.com/*` | 이 두 사이트에서만 동작 |
| `web_accessible_resources: src/inject.js` | 페이지 컨텍스트에 꽂을 스크립트 한 개만 노출 |

`tabs` 같은 광범위한 권한은 쓰지 않습니다. 팝업은 활성 탭의 콘텐츠 스크립트에
**직접 물어보는 방식**이라 탭 목록 접근 권한이 필요 없습니다.

## 🧪 개발 메모

- 빌드 도구·의존성 없음. 폴더 그대로 로드됩니다.
- 모든 외부 데이터 처리는 `try-catch` 로 감싸 **실패해도 페이지를 깨뜨리지 않습니다.**
- 정렬은 원본 DOM 노드를 **이동만** 합니다(복제·삭제 없음). "원래 순서"로 완전히 되돌아갑니다.
- JSON 탐색은 반드시 **너비 우선(FIFO)** 이어야 합니다.
  스택(LIFO)으로 돌면 같은 배열의 항목이 역순으로 나와 "원래 순서"가 피드와 반대로 뒤집힙니다.
- 오버레이는 카드 전체가 아니라 **썸네일 링크**에 붙입니다. 카드 기준으로 붙이면
  아래쪽 캡션·작성자 영역을 덮습니다. 링크가 `display:inline` 이면 테두리가 그려지지 않으므로
  `isBox()` 로 실제 박스인지 확인한 뒤 안쪽 컨테이너 → 카드 전체 순으로 물러납니다.
  (`offsetHeight` 는 인라인 링크에서도 블록 자식 크기를 보고하므로 그것만 믿으면 안 됩니다)
- **manifest 의 `content_scripts` 항목 두 개가 같은 js 파일을 공유하면 크롬이 두 번째 항목을
  조용히 건너뜁니다.** 그래서 `world: "MAIN"` 으로 따로 등록하는 대신, 콘텐츠 스크립트가
  `<script>` 태그로 `inject.js` 를 꽂는 방식을 씁니다. 덕분에 `constants.js` 를 한 곳에만 두면서
  요구 크롬 버전도 111 → 102 로 낮아졌습니다.
- 확장이 붙었는지는 콘솔에서 `document.documentElement.dataset.feedSorter` 로 확인할 수 있습니다.
- **무한 스크롤 때 화면이 위로 튀던 원인은 셋이 겹친 것이었습니다.**
  ① `S.reordering` 플래그는 아무것도 막지 못했습니다 — MutationObserver 콜백은 재정렬 함수가
  끝난 뒤 마이크로태스크로 오므로 그때는 이미 플래그가 내려가 있고, 우리가 옮긴 노드·붙인 뱃지가
  관찰자를 다시 깨워 재정렬을 반복시켰습니다. → 우리 DOM 쓰기 직후 `mo.takeRecords()` 로 기록을 버립니다.
  ② 새 카드가 화면 위쪽 정렬 자리에 끼어들면 그 높이만큼 보던 내용이 밀렸습니다.
  → 재정렬 전에 "화면 안 맨 위의, 이미 정렬 자리가 안정된 카드"를 앵커로 잡아 top 을 기억하고,
  끝난 뒤 그 차이만큼 실제 스크롤 컨테이너(없으면 window)를 보정합니다.
  ③ 사용자가 아직 드래그 중인데 재정렬이 즉시 일어났습니다. → `scroll` 을 capture 로 잡아
  (스크롤 컨테이너까지 보이게) 마지막 스크롤 뒤 `SCROLL_IDLE_MS` 가 지나야 재정렬합니다.
  뱃지는 스크롤 중에도 바로 붙습니다.
- 해시태그 칩은 카드 링크(`<a>`) 안에 들어가므로 `<a>` 를 중첩하지 않고 `<span>` + 캡처 단계
  click 핸들러(`preventDefault`/`stopPropagation`)로 새 탭을 엽니다. 다운로드 버튼과 같은 방식입니다.
- **"못 읽었다"와 "읽을 게 없었다"를 구분해야 합니다.** Instagram 의 `/api/graphql` 처럼
  온갖 질의가 한 주소로 오가는 엔드포인트에서는, 추출 0건을 곧바로 구조 변경으로 보면
  거의 다 오탐입니다. `looksLikeMedia()` 로 "영상처럼 생긴 노드"가 있는지 먼저 보고,
  있을 때만 경고합니다.
- 검색 결과 응답은 통계가 비어 오기도 합니다. 그래도 미디어가 확실하면 받아들여
  카드 매핑·게시일에 씁니다. 통계 정렬에서는 자동으로 뒤로 밀립니다.
